# 4. ОСНОВНАЯ ИГРА «ВЫБЕРИ БАК»

Это центральный игровой режим первой версии приложения.

## 4.1. Суть игры

На экране появляется изображение определённого отхода.

Игрок должен определить, куда необходимо выбросить этот отход, и перетащить его изображение непосредственно в соответствующий контейнер.

**Основная механика — полноценный Drag & Drop с управлением пальцем.**

Это принципиальное требование. Не заменяй её обычным нажатием на кнопки выбора ответа.

## 4.2. Механика перетаскивания

Реализуй следующий сценарий:

1. На экране отображается изображение отхода.
2. Игрок касается изображения пальцем.
3. Изображение захватывается и следует за движением пальца.
4. Игрок перемещает его по экрану.
5. Игрок отпускает палец над одним из контейнеров.
6. Игра определяет, в какую область попал объект.
7. Система проверяет правильность выбора.

Если ответ правильный:
- Покажи положительную визуальную обратную связь.
- Воспроизведи соответствующий звук, если звуковые эффекты включены.
- Обнови счётчик прогресса.
- Перейди к следующему отходу.

Если ответ неправильный:
- Покажи понятную отрицательную обратную связь.
- Не засчитывай ответ.
- Верни объект на исходную позицию.
- Предоставь возможность повторной попытки.

Перетаскивание должно быть плавным, отзывчивым и корректно работать на реальных сенсорных экранах Android.

Предусмотри корректную обработку:
- Начала перетаскивания.
- Перемещения пальца.
- Отпускания пальца.
- Попадания в область контейнера.
- Отмены перетаскивания.
- Повторных попыток.
- Случаев, когда объект отпущен вне контейнеров.

## 4.3. Игровые контейнеры

В игре должны присутствовать пять вариантов назначения отходов, соответствующих ТЗ заказчика:

**1. Серый бак**

Предназначен для пищевых отходов и всего, что содержит пищевые отходы, а также перечисленных в ТЗ категорий: бумажных носовых платков, целлофановых пакетов, бумажной посуды, средств личной гигиены, чеков, тюбиков из-под зубной пасты, бумаги для выпечки и других указанных отходов.

**2. Синий бак**

Контейнеры с синей наклейкой и надписью «Вторсырьё».

Предназначены для отходов, направляемых на переработку: бумаги, пластика, стекла и металла согласно правилам и исключениям, приведённым в оригинальном ТЗ.

**3. Бункер-накопитель**

Предназначен для отходов размером более 0,5 метра в длину, которые не помещаются в обычные синие контейнеры.

Отходы не должны содержать остатков пищи.

**4. Контейнер для опасных отходов**

Предназначен для безопасного сбора опасных отходов, включая люминесцентные лампы, разбитые термометры с остатками ртути и использованные батарейки.

**5. Социальные проекты по приёму вещей и отходов**

Предназначены для передачи вещей на повторное использование, благотворительность и дальнейшую переработку.

В ТЗ перечислены одежда, обувь, подушки, одеяла, детские игрушки, а также отдельные категории электронных и других отходов.

Для всех пяти вариантов необходимо предусмотреть:
- Собственное изображение контейнера.
- Название.
- Визуальное оформление.
- Область, принимающую перетаскиваемые объекты.

Не придумывай дополнительные правила сортировки. Используй данные заказчика.

# 6. СИСТЕМА ДАННЫХ ОБ ОТХОДАХ

Это один из важнейших компонентов проекта.

Необходимо создать отдельную систему хранения игровых объектов.

Информация об отходах не должна быть жёстко прописана в игровых скриптах.

Каждая запись должна поддерживать следующие поля:

- Уникальный идентификатор.
- Название отхода.
- Изображение.
- Класс опасности.
- Правильная категория утилизации.
- Дополнительное описание.
- Дополнительные параметры при необходимости.

Используй удобный формат структурированных данных, например JSON, с возможностью последующего расширения.

## 6.1. Редактор базы отходов

Предусмотри отдельный интерфейс управления базой.

Необходимо реализовать:

- Создание нового отхода.
- Редактирование существующего отхода.
- Удаление отхода.
- Изменение названия.
- Изменение изображения.
- Изменение класса опасности.
- Изменение правильного контейнера.
- Добавление и изменение описания.

Изменения должны сохраняться между запусками приложения.

Отдели исходные данные от пользовательских изменений, чтобы обновление контента не уничтожало уже внесённые записи.

## 6.2. Перенос данных из ТЗ

Изучи оригинальный документ заказчика и извлеки из него перечень отходов.

Не нужно вручную переписывать весь документ в игровые скрипты.

Подготовь структурированную базу данных.

Для каждого объекта используй сведения, которые действительно присутствуют в исходном ТЗ.

Особенно важно сохранять различия между похожими отходами.

Например, чистая бумага и загрязнённая бумага могут иметь разные классы опасности и способы утилизации.

Не объединяй такие записи в один универсальный объект.

## 6.3. Работа с изображениями

Учитывай все замечания заказчика к изображениям:

- Если требуется белый фон — используй белый фон.
- Если изображение обозначено как стоковое и требует замены — не выдавай его за готовое.
- Если требуется показать загрязнение, остатки еды, жира или другие особенности — они должны быть визуально заметны.
- Не используй случайные изображения, не соответствующие названию отхода.

Если подходящего изображения нет, создай временный визуальный placeholder и внеси его в список незавершённых ресурсов.

Не подменяй отсутствующие фотографии неподходящими картинками.

# 7. КЛАССЫ ОПАСНОСТИ

Предусмотри хранение классов опасности от I до V.

В соответствии с ТЗ:

- I класс — чрезвычайно опасные отходы.
- II класс — высокоопасные отходы.
- III класс — умеренно опасные отходы.
- IV класс — малоопасные отходы.

Класс опасности должен быть связан с конкретным отходом, а не назначаться произвольно.

На текущем этапе это прежде всего информационный параметр базы отходов и дополнительный элемент оформления игры.

# 8. АРХИТЕКТУРА И СТРУКТУРА ПРОЕКТА

Проект должен быть модульным.
